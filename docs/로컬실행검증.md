# 로컬 실행 검증

검증일: 2026-11-17
환경: Windows, Docker Desktop, Docker Compose, MySQL 8.4

## 확인한 항목

- Docker Compose로 WaterAPI와 MySQL 실행
- MySQL 컨테이너 healthy 상태 확인
- /actuator/health 응답 UP 확인
- 시설과 점검일지 등록, 처리 상태 변경
- stub 프로필에서 분석 결과 저장과 조회
- docker compose down 후 up -d로 재생성
- 재생성 후 점검일지, 처리 상태, 분석 결과와 분석 시각 유지
- Java 시간대를 Asia/Seoul로 설정
- 새 분석 결과의 시각이 한국 시간과 일치함을 확인
- MySQL에서 시설, 점검일지, AI 분석 테이블을 직접 조회했다.
- Flyway 이력에서 V1__initial_schema.sql의 success=1을 확인했다.
- 점검일지와 분석 결과를 JOIN하여 처리 상태와 분석 시각을 확인했다.
- 실제 OpenAI 분석에 사용한 점검일지는 테스트 후 삭제했다.
- 삭제 후 새로 등록한 점검일지에는 stub 분석 결과가 저장됨을 확인했다.

## 검증 범위

- Docker 환경의 AI 분석은 stub으로 확인했다.
- Docker 밖의 openai 프로필과 Docker의 prod,openai 프로필에서 실제 OpenAI 분석을 확인했다.
- Docker에서 PUMP-B 점검 내용으로 실제 분석 결과를 생성하고 조회했다.
- 기본 Compose 설정으로 전환한 뒤 새 점검일지에서 stub 분석 결과를 확인했다.
- OpenAI API 키는 PowerShell 환경변수로 전달하고 소스 파일에는 기록하지 않았다.
- AWS 배포는 아직 검증하지 않음.

## MySQL 백업 및 복원 검증 (2026-11-17)

- mysqldump로 waterapi DB의 테이블 구조와 데이터를 백업했다.
- 백업 명령 종료 코드 0과 Dump completed 문구를 확인했다.
- SQL 백업 파일은 Git 저장소 밖의 WaterAPI-backups 폴더에 보관했다.
- PC의 백업 파일을 컨테이너로 복사하여 별도 DB인 waterapi_restore_check에 복원했다.
- 복원 결과: 시설 1건, 점검일지 2건, AI 분석 2건, Flyway 이력 1건.
- CHECKSUM TABLE EXTENDED로 원본과 복원본의 네 테이블 체크섬이 모두 일치함을 확인했다.
- 복원된 점검 내용과 분석 결과의 한글 및 분석 시각이 유지됨을 확인했다.
- 기존 waterapi DB를 유지한 상태에서 같은 MySQL 컨테이너 내 별도 DB로 복원을 검증했다.
