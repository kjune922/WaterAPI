# AWS 배포 준비 및 실행 기록 양식

현재 상태: 배포 준비. AWS 리소스를 생성하지 않았으며 비용도 발생시키지 않았다.

## 구성
EC2에서 Docker로 Spring Boot를 실행하고, 비공개 RDS MySQL에 연결하는 단일 인스턴스 데모를 목표로 한다.
다중 고객사 분리, 고가용성, 오토스케일링을 구현한 구성으로 설명하지 않는다.

## 실제 배포 전
1. GitHub CI의 Java 테스트와 MySQL smoke 작업을 통과한다.
2. AWS 계정, 리전, 실습 예산과 종료 날짜를 정한다.
3. EC2의 보안 그룹은 개인 접속 IP만 허용한다. RDS의 3306은 EC2 보안 그룹에서만 허용한다.
4. RDS는 공개 접근을 끄고 새 빈 waterapi 데이터베이스를 준비한다.
5. EC2에 SSM 접속 역할을 연결하고 ECR은 필요한 읽기 권한만 부여한다.
6. 비밀번호는 저장소, 이미지, 명령 히스토리에 입력하지 않는다. 런타임 환경 파일은 소유자 읽기만 허용한다.
7. RDS JDBC는 TLS 인증서 검증을 적용한다. 로컬 Compose의 useSSL=false 값을 재사용하지 않는다.

## 배포 순서
- 검증한 커밋의 이미지를 생성하고 커밋 SHA 태그로 ECR에 저장한다.
- EC2에서 해당 태그를 가져온다.
- prod,stub 프로필로 먼저 시작한다.
- /actuator/health, 시설 등록, 점검 등록, 조회, 분석, 수정 후 기존 결과 삭제를 확인한다.
- 실제 AI는 키와 비용 설정을 확인한 다음 prod,openai로 별도 검증한다.
- API 키, DB 비밀번호, 점검 원문을 로그 또는 화면 캡처에 포함하지 않는다.

## 배포 실패와 복구
- 컨테이너 상태, 애플리케이션 로그, DB 연결, Flyway 이력을 순서대로 확인한다.
- 이전 이미지 태그를 기록하고 호환되는 스키마에서 이전 이미지로 되돌린다.
- DB 변경은 이미지 복구만으로 취소되지 않는다. 이후 마이그레이션마다 호환성과 백업 복구 방법을 검토한다.
