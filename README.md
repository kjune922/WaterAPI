# WaterAPI | 시설 점검과 AI 분석

상하수도 시설과 점검일지를 관리하는 개인 웹 프로젝트입니다. 사용자는 점검 원문과 AI 분석을 비교하고, AI가 제안한 값을 그대로 확정하거나 수정해서 확정할 수 있습니다.

**Java 17 · Spring Boot 4.1 · Spring Data JPA · Thymeleaf · MySQL · Flyway · OpenAI · Docker · AWS**

## 전체 흐름

```mermaid
flowchart TD
    A["시설 등록"] --> B["점검일지 작성"]
    B --> C["AI 분석 요청"]
    C --> D["AI 원본 저장 · 검토 대기"]
    D --> E["점검 원문과 AI 원본 비교"]
    E --> F["그대로 또는 수정 후 확정"]
    D --> G["목록·대시보드 조회 · AI 원본 위험도 기준"]
    B --> H["점검일지 수정 · 기존 분석과 확정본 삭제"]
    H -- "사용자가 재분석 요청" --> C
```

## 문제와 해결, 확인 결과

| 문제 | 해결 | 확인 결과 |
| --- | --- | --- |
| 검토 중 값을 바꾸면 AI가 처음 제안한 내용을 잃을 수 있습니다. | AI 원본을 보존하고 사용자 확정본과 확정 시각을 별도로 저장합니다. 목록·대시보드의 위험도는 AI 원본 기준입니다. | PR #3 병합 전, 사용자가 집 PC의 `feature/analysis-review`에서 그대로 확정과 위험도·권장 조치 변경 후 확정을 직접 실행하고 화면을 공유했습니다. |
| 같은 분석에 확정 요청이 두 번 들어올 수 있습니다. | 점검일지와 분석 ID가 맞고 검토 대기인 경우에만 확정합니다. | MySQL에 동시에 보낸 두 요청 중 하나만 성공했습니다. |
| 일지를 수정하면 이전 분석과 확정본의 근거가 달라집니다. | 일지 수정과 기존 분석 행 삭제를 한 트랜잭션으로 처리합니다. | 수정에 성공하면 원본과 확정본이 함께 사라졌고, 삭제 실패 시에는 일지와 확정본이 모두 보존됐습니다. |
| 점검 목록에서 시설 이름을 건별로 조회했습니다. | `EntityGraph`로 점검일지와 시설을 함께 조회합니다. | 점검일지 30건 중 첫 10건을 읽을 때 SQL 실행 횟수가 12회에서 2회로 줄었습니다. |

병합 후에는 사용자가 로컬 `main`을 업데이트하고 작업 트리와 커밋을 확인했습니다.

현재 사용자 인증, 담당자별 확정 기록, 확정본 직접 정정은 지원하지 않습니다. [구현 설명](docs/README.md) · [개발·CI 검증 결과와 AWS 실습 기록](docs/VERIFICATION.md)

## 로컬에서 확인하기

Java 17에서 Windows는 `.\gradlew.bat bootRun`, Linux와 macOS는 `bash gradlew bootRun`을 실행한 뒤 브라우저에서 `http://localhost:8080`을 엽니다. 기본 설정은 H2 파일 DB와 정해진 분석값을 돌려주는 Stub을 사용하므로 API 키 없이 확인할 수 있습니다.
